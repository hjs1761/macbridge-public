# macbridge

> 이 저장소는 공개용 스냅숏입니다. 개발은 비공개 저장소에서 하고, 설계·계획 문서(실기기 주소가 남은 검증 기록)는 넣지 않았습니다.

맥 사이에 **한/영 입력 소스를 맞춰 주는** 작은 데몬. 원격 접속(Jump Desktop 등)으로 다른 맥을 쓸 때
`Caps Lock` **한 번**이면 양쪽 입력 소스가 함께 바뀐다.

> 이전 이름은 `ime-sync`. 기능이 IME 를 넘어서게 되어(액션 브리지, Phase 2) 개명했다.

## 왜 필요한가

Jump Desktop(Fluid, Mac→Mac)은 **클라이언트에서 조합을 끝낸 문자**를 호스트로 보낸다. 그래서 양쪽 입력 소스가 어긋나면 입력이 깨진다:

| 클라(접속하는 쪽) | 호스트(접속받는 쪽) | Jump Desktop Fluid | macOS 화면 공유 |
|---|---|---|---|
| `A` | `A` | ✅ 영문 | ✅ 영문 |
| `한` | `한` | ✅ 한글 | ✅ 한글 |
| `A` | `한` | ❌ 아무것도 안 찍힘 | ❌ `dkssud` (영문 그대로) |
| `한` | `A` | ⚠️ 자소분리 | ⚠️ 자소분리 |

**Parsec 은 증상이 또 다르다** — 자소분리가 아니라 **"한글 모드인데 영문만 입력되는"** 상태가
된다(키코드를 보내니 호스트가 조합하는데, 호스트 입력 세션이 꼬이면 IME 를 통째로 무시한다).
겉모습은 다르지만 **원인도 해법도 같다** — 캡스락 두 번(포커스 바운스)으로 풀리고, 한 번 풀리면
계속 정상이다. 2026-08-08 실측.

**두 도구가 같은 문제를 겪는다**(2026-08-08 실측, 맥북→집미니). 3행의 차이는 호스트 IME 처리
방식의 세부 차이일 뿐이고 — Fluid 는 영문을 삼키고 화면 공유는 흘려보낸다 — 핵심인 **자소분리는
동일**하다. 즉 클라가 조합해서 보내고 조합 세션이 전선을 건너며 끊어지는 구조가 공통이다.
**이 도구는 Jump Desktop 전용이 아니다.**

그런데 전환 키가 각각 한쪽씩만 바꾼다 — `Caps Lock`은 클라만, `Ctrl+Space`는 호스트만. 그래서 언어를 바꿀 때마다 **두 번** 눌러야 하고, 한 번 어긋나면 두 번 누르기로는 영영 못 맞춘다(둘 다 토글이라 같이 뒤집힘).

## 왜 이 방식인가 — 실패한 접근들

Karabiner-Elements로 `Caps Lock` 한 번에 양쪽을 바꾸려 했으나 **전부 실패**했다. 보낸 키를 세 번 바꿔봤지만 결과가 같았다:

| 시도 | 결과 |
|---|---|
| `Ctrl+Space` 전송 | 로컬만 전환, 호스트 무반응 |
| `⌃⌥⇧K` 전송 | 로컬만 전환, 호스트 무반응 |
| `F18` 전송 + Jump 의 Key Conversions 로 `⌃⌥F12` 변환 | 로컬만 전환, 호스트 무반응 |

**손으로 누른 같은 조합은 매번 호스트에 잘 전달됐다.** 즉 조합이나 키의 문제가 아니라 **이벤트 출처**의 문제 — Jump Desktop이 Karabiner 가상 키보드에서 나온 키 이벤트를 원격으로 넘기지 않는다. 우회 불가.

그래서 **키를 보내지 않는다.** 입력 소스가 "바뀐 사실"만 알리고, 받은 쪽이 **자기 머신에서 로컬로** 자기 입력 소스를 바꾼다. 원격 도구가 경로에 아예 없으므로 위 벽이 존재하지 않는다.

```
맥 A (both)                              맥 B (both)
  입력 소스 변경 감지
  → "<token> ko <ts>" 전송  ──UDP:8765──→  수신 → TISSelectInputSource("ko")
  ←────────────────────────────────────  (반대 방향도 동시에)
```

**어느 원격 도구를 쓰든, 어떤 키로 바꾸든 무관하게 동작한다.** 실검증은 **Jump Desktop Fluid** ·
**macOS 기본 화면 공유** · **Parsec** 세 가지에서 했다(2026-08-08). 나머지 5종은 미검증이다.

### 키를 안 보기 때문에 전환 방법을 가리지 않는다

감지하는 것은 `kTISNotifySelectedKeyboardInputSourceChanged` 알림과 TIS 폴링뿐이다 —
**무슨 키가 눌렸는지는 알지도 못한다.** 그래서 `Caps Lock`, 오른쪽 `Command`(윈도우식 한/영),
메뉴바 클릭, Karabiner 로 매핑한 커스텀 키가 전부 똑같이 동작한다. 복구 제스처도
"캡스락 두 번"이 아니라 **"언어가 1초 내 왕복"** 이라 마찬가지다.

### `Ctrl+Space` — 도구마다 반대로 동작한다 (2026-08-08 실측)

| 도구 | Ctrl+Space 가 바꾸는 것 |
|---|---|
| Parsec | **로컬**(내 맥) — macbridge 가 감지해 호스트를 맞춘다. 완전 정상 |
| Jump Desktop | **호스트만** — 로컬은 그대로다 |

호스트만 바뀌는 경우, 한때는 클라(권한자)가 "어긋났다"고 보고 `recover` 로 **되돌려서**
사용자 눈엔 "깜빡이더니 그대로"였다 — macbridge 가 한영전환을 취소하는 셈이었다.
지금은 `shouldFollowPeer` 가 **따라간다**(위 자동복구 절 참조). 어느 도구든 언어는 맞는다.

⚠ **남는 문제는 언어가 아니라 세션이다.** `Ctrl+Space` 가 호스트에 닿으면 그 포커스의 입력
세션이 꼬이고, 언어가 맞아도 자소분리·"한글인데 영문만 입력"이 남는다. 꼬임은 **포커스
바운스로만** 풀린다.

그럼 왜 자동으로 안 푸나 — **바운스가 조합 중인 글자를 깨기 때문이다.** 매 전환마다 바운스하면
고치려던 증상을 우리가 만든다(2026-08-08 실증: 제스처 창을 2초로 넓혔더니 정상 전환이 전부
제스처로 잡혀 자소분리가 났다). 그래서 **사용자가 필요할 때 부르는 것**이 올바른 설계다.

→ 안내 순서는 **「지금 정렬」이 먼저다**(2026-08-08 실사용: "자소분리 생기는 경우 지금 정렬
클릭하면 바로 정상"). 제스처는 1초 창에 의존해 지구본 키처럼 느린 키는 놓치지만, **메뉴 클릭은
타이밍이 없어 언제 눌러도 한 번에 된다.** 캡스락 톡톡은 손이 키보드에 있을 때의 빠른 길이고,
전환 키로 캡스락을 안 써도 복구 키로는 쓸 수 있다(원격 창 최전면에서도 먹는 유일한 키).
아예 안 겪고 싶으면 시스템 설정에서 `⌃Space` 를 꺼도 된다.

⚠ 문서에서 캡스락을 1순위로 두면 안 된다 — **타이밍 실패가 "안 되는데요"로 돌아온다.**

> 그러므로 "사용자가 쓰는 전환 키를 설정하게 하자"는 **넣으면 안 되는 기능이다.** 특정 키를
> 감지하려면 입력 모니터링 권한이 필요해지는데, "추가 권한 0개 · 키 입력 미수집"이 이 도구의
> 신뢰 근거다. Karabiner 로 키를 다루려던 접근이 3전 3패한 지점도 정확히 여기다.

## 설치

### 앱으로 (권장)

1. Releases 에서 `MacBridge-x.y.dmg` 다운로드
2. 열어서 `MacBridge.app` 을 **응용 프로그램**으로 드래그
3. 실행 — 메뉴바에 `한`/`A` 가 뜬다. **데몬은 앱이 알아서 등록**한다
4. 두 번째 기기부터는 설정 → 기기 → **「기존 기기에 연결…」** 로 연결 코드를 붙여넣는다

⚠ 공증(Phase 4-C) 전 배포본은 처음 열 때 Gatekeeper 경고가 뜬다. **macOS 15 Sequoia 부터
`우클릭 → 열기` 우회가 삭제됐다** — 그 방법을 안내하면 사용자는 앱을 못 연다. 지금 유효한 경로는:

1. 앱을 **한 번 실행해 본다.** 경고가 뜨면 닫는다 — **이걸 건너뛰면 2번에 항목이 안 생긴다**
2. 시스템 설정 → **개인정보 보호 및 보안** → 맨 아래 **보안** 섹션
3. "MacBridge 이(가) 차단되었습니다" 옆 **그래도 열기** → 암호 입력

공증이 붙으면 이 과정이 통째로 사라진다. 그래서 **일반 사용자 대상 배포는 공증 이후**가 맞다.

> 앱은 실행파일을 `~/Library/Application Support/MacBridge/` 로 복사해 **그 사본으로 데몬을 돌린다.**
> 번들 안 경로로 데몬을 돌리면 macOS 가 그 프로세스를 앱 인스턴스로 봐서 **`open` 이 앱을 못 띄운다**(실측).

### 소스에서 빌드 (개발자용)

**모든 기기에서** `~/projects/menubar-tools/macbridge/` 에서 (Syncthing으로 전파됨):

```bash
# 양방향(기본) — 나머지 기기들의 IP 를 전부 나열
./install.sh 100.64.0.2 100.64.0.3

# 한 방향만 쓰고 싶다면
./install.sh --mode serve                      # 수신 전용
./install.sh --mode watch 100.64.0.1        # 송신 전용

# 재설치(빌드만 갱신, 설정은 그대로)
./install.sh
```

양방향으로 깔아도 **`only_app` 덕분에 지금 원격을 걸고 있는 쪽만 송신**한다 — 뷰어가 최전면인 기기가 곧 클라이언트이기 때문. 방향별로 다르게 설정할 필요가 없다.

필요한 것: Xcode Command Line Tools (`xcode-select --install`).

#### 빌드 타깃 — `scripts/build-config.sh` 한 곳에서 정한다

`install.sh`(개발용, 이 기기 아키텍처만)와 `scripts/package_app.sh`(배포용, **universal**)가
같은 `MIN_MACOS` 를 읽는다. **`swiftc -target` 을 빼면 빌드한 맥의 OS 버전이 그대로 박힌다** —
Info.plist 에 `13.0` 이라 적어 놔도 바이너리는 `minos 26.0` 이라 macOS 13 사용자가 그냥
못 여는 상태가 된다(2026-08-08 발견, `vtool -show-build` 로 확인). 개발 빌드에도 같은 타깃을
주는 이유는 **macOS 13 에 없는 API 를 쓰면 그 자리에서 컴파일 에러가 나게** 하기 위해서다.

`package_app.sh` 는 조립 후 슬라이스별 `minos` 와 plist 값이 일치하는지 검사하고 어긋나면 멈춘다.

### ⚠ 방화벽이 켜져 있다면

macOS 방화벽은 이 데몬의 **외부 수신만** 조용히 막는다. 루프백 테스트는 통과하기 때문에
증상이 "아무 로그도 안 남음"으로만 나타나 원인을 놓치기 쉽다. 백그라운드 데몬이라
"수신 허용?" 팝업을 사람이 볼 수 없어 사실상 거부로 굳는다. `install.sh` 가 감지해서 알려 주지만,
조치는 손으로 해야 한다:

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add ~/bin/macbridge
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp ~/bin/macbridge
```

### ⚠ 토큰은 모든 기기가 같아야 한다

첫 설치 때 `~/.config/macbridge/config.json` 의 `token` 이 생성된다. 그 값을 **다른 기기에도 똑같이** 넣어야 한다.

```bash
# 한쪽에서 확인
python3 -c "import json;print(json.load(open('$HOME/.config/macbridge/config.json'))['token'])"
```

다른 기기의 `config.json` 에서 `token` 값을 그 값으로 바꾸고 `./install.sh` 재실행.
(구버전 `ime-sync` 를 쓰던 기기라면 `~/.config/ime-sync/token` 을 **자동으로 물려받는다** — 손댈 것 없음)

## 설정

**보통은 메뉴바 → `설정…` 에서 다 된다.** `config.json` 을 열 일이 없다.

```
┌─ macbridge 설정 ──────────────────────────────┐
│  [일반]  [원격 도구]  [기기]  [고급]            │
└───────────────────────────────────────────────┘
```

| 탭 | 할 수 있는 것 |
|---|---|
| **일반** | 기기 이름 · 한/영 자동 동기화 · 자소분리 자동복구 |
| **원격 도구** | 쓰는 원격 앱 체크. **설치된 것만 활성**, 나머지는 `(미설치)` 회색. 목록에 없으면 **`+ 지금 쓰는 원격 앱 자동 감지`** — 누르고 5초 안에 원격 창을 앞으로 가져오면 잡아 준다(**번들 ID 를 몰라도 된다**) |
| **기기** | 연결된 기기 상태(●/○) · 삭제 · 연결 테스트 · **새 기기 추가**(코드 발급) / **기존 기기에 연결**(코드 붙여넣기) · IP 직접 추가 |
| **고급** | 연결 코드(복사·교체) · 포트 · 허용 대역 · 설정 파일/로그 열기 |

바꾸는 즉시 저장되고 **데몬이 재시작 없이 반영**한다(포트만 예외 — 그때는 안내가 뜬다).

⚠ **Chrome 원격 데스크톱**은 목록에 없다. 웹앱이라 번들 ID 가 `com.google.Chrome` 이어서
체크하면 **평소 웹서핑 중에도 동기화가 걸린다.** 자동감지로 잡으면 그 경고가 뜬다.

### 새 기기 붙이기

1. **기존 기기**에서 설정 → 기기 → `+ 새 기기 추가…`
   코드가 뜨고 **클립보드에 복사**된다 (`mb1.100.64.0.3.8765.482917`, 120초 유효)
2. **새 기기**에서 설정 → 기기 → `기존 기기에 연결…` → 붙여넣기
3. 끝. 연결 코드(토큰)와 기기 목록이 자동으로 맞춰지고, 새 기기가 나머지 기기들에게 알아서 인사한다

터미널에서 해도 된다: `macbridge pair mb1.100.64.0.3.8765.482917`

⚠ 코드는 **한 번 쓰면 닫히고**, 120초가 지나거나 **5회 틀리면 폐기**된다. 그때는 1번부터 다시.
⚠ 일부 기기에 인사를 못 하면 **어느 기기인지 그대로 알려 준다** — 그 기기가 꺼져 있거나
방화벽에 막힌 경우다. 나중에 `연결 테스트` 로 확인하면 된다.

> 🔒 연결 창은 **평소 닫혀 있고** 버튼을 눌렀을 때만 열린다. 그래도 **코드를 아는 상대에게
> 토큰을 준다**는 성질은 남으므로, 코드를 아무 데나 붙여넣지 말 것(유출돼도 IME 변경까지이고
> 파일 접근·코드 실행은 불가).

### config.json (참고용)

아래는 파일을 직접 볼 때를 위한 참고다. `~/.config/macbridge/config.json` 이 유일한 원본이고,
`install.sh` 는 이 파일을 **병합 갱신**하므로 손으로 넣은 키는 지워지지 않는다.

```json
{
  "mode": "both",
  "port": 8765,
  "token": "…",
  "peers": ["100.64.0.2", "100.64.0.3"],
  "allow_from": ["tailscale", "lan"],
  "ime_sync": {
    "enabled": true,
    "only_app": "com.p5sys.jump.mac.viewer",
    "heartbeat_sec": 0
  },
  "device": { "id": "5BBB4700-…", "name": "맥북" },
  "hotkeys": [ { "combo": "ctrl+opt+shift+k", "action": "realign" } ]
}
```

| 키 | 뜻 |
|---|---|
| `mode` | `serve`(수신만) / `watch`(송신만) / `both`(기본) |
| `port` | UDP 수신 포트. 모든 기기가 같게 |
| `token` | 공유 비밀. **모든 기기 동일해야 함** |
| `peers` | 알림을 보낼 상대. `IP` 또는 `IP:PORT`. ⚠ **이름이 아니라 IP** |
| `allow_from` | 수신 허용 대역. `tailscale`(100.64/10) · `lan`(RFC1918) · `any` · 명시 CIDR(`10.0.0.0/8`). 루프백은 항상 허용 |
| `ime_sync.enabled` | 한/영 동기화 on/off |
| `ime_sync.only_app` | 이 앱이 최전면일 때만 송신. **문자열 하나 또는 배열** 둘 다 됨. `null`/빈 값이면 항상. 예: `["com.p5sys.jump.mac.viewer", "tv.parsec.www"]` |
| `ime_sync.heartbeat_sec` | 변화가 없어도 되풀이해 알리는 주기(초). **기본 `0`(끔) — 켜면 한글 조합이 깨진다.** 아래 설계 메모 참조 |
| `ime_sync.auto_recover` | 자동정정 시 **포커스 바운스까지** 수행(기본 `true`). 꼬인 입력 세션은 IME 정렬로 안 풀리기 때문. 끄면 정렬만 |
| `device.id` | 기기 고유 ID. `install.sh` 가 생성하며 **불변**(재설치해도 보존). `peers` 목록의 정체성 |
| `device.name` | 사람이 읽는 기기 이름. 기본은 ComputerName — 자유롭게 고쳐도 보존됨 |
| `hotkeys` | 전역 핫키 목록. `combo` 는 `ctrl/opt/shift/cmd + 키`, `action` 은 현재 `realign` 만. 조합이 다른 앱과 충돌하면 여기서 바꾼다 |

## 메뉴바

`install.sh` 가 데몬과 **별개 LaunchAgent**(`com.hjs.macbridge.menubar`)로 띄운다. UI 가 죽어도
IME 동기화는 계속 돈다.

- **아이콘** = 현재 언어(`한`/`A`). **온라인 피어와 언어가 다르면 주황색**, 데몬 무응답이면 빨간 `⚠`.
  macOS 기본 입력 소스 메뉴와 글자는 같지만 **불일치 경고**는 기본 메뉴가 못 하는 일이다.
- **지금 정렬** = `realign` — 전 기기 IME 정렬 + **누른 기기를 포함한** 포커스 바운스.
  ⚠ 핫키 `⌃⌥⇧K` 는 Jump 뷰어가 최전면이면 삼켜지는데, **메뉴 클릭은 그 벽을 우회한다.**
  💡 **자소분리가 난 그 기기에서 누르는 게 맞다** — 꼬인 입력 세션은 그 기기에 있기 때문.
- **IME 동기화** 토글 — 런타임 전환 + `config.json` 에 영속화.
- **연결 테스트** — 피어별 `echo` 왕복 시간. **방화벽(ALF) 차단·토큰 불일치·IP 변경·데몬 중지**를 한 번에 가려낸다.
  (방화벽 차단은 루프백 테스트를 통과해 버려서, 이 왕복이 없으면 "아무 로그도 안 남음"으로만 나타난다)
- **메뉴바 종료** 는 메뉴바만 내린다. 데몬은 계속 돈다.

⚠ **Ice·Bartender 같은 메뉴바 관리 앱을 쓰면 새 아이템이 숨김 영역에 들어가 안 보인다.**
macOS 는 `isVisible = true` 로 보고하므로 버그로 오인하기 쉽다. 숨김 영역을 펼쳐 `⌘`+드래그로
꺼내면 되고, `autosaveName` 덕에 위치는 유지된다.

### 자소분리 — 원인·예방·치유 (2026-08-07 규명)

**자소분리의 정체는 IME 불일치가 아니라 "꼬인 입력 세션"이다.** `Ctrl+Space`(호스트 전용
전환)를 누르는 순간 그 포커스의 입력 세션이 꼬이고, 이후 IME 를 완벽히 정렬해도
(캡스락 왕복·realign·자동정정 전부) **그 세션은 안 풀린다** — 전부 실측으로 확인.

| | 방법 |
|---|---|
| **자동 ⭐** | **아무것도 안 해도 1~5초 내 복구된다** — 자동복구가 IME 정렬 + 포커스 바운스를 대신한다(아래 절) |
| **수동 ⭐** | **캡스락을 1초 안에 두 번**(톡톡). 즉시 전 기기 IME 정렬 + **포커스 바운스**. 뷰어 최전면에서도 먹는 유일한 키 경로 |
| **예방** | `Ctrl+Space` 는 호스트만 바꿔 꼬임을 만드므로 시스템 설정 → 키보드 단축키 → 입력 소스에서 **"이전 입력 소스 선택(⌃Space)" 해제 권장** |
| 수동 치유 | **다른 창을 클릭했다가 원래 창으로 복귀** — 캡스락 더블탭이 하는 일을 손으로 하는 것 |
| 정렬만 | `⌃⌥⇧K` (realign) — 캡스락 더블탭과 같은 동작. ⚠ Jump 뷰어가 최전면이면 **뷰어가 키를 삼켜서 안 먹는다**(실측). 뷰어 밖에서만 유효 |

#### 캡스락 더블탭이 복구가 되는 이유

1초 내 왕복(`ko→en→ko`)은 동기화 관점에서 **순효과가 0인 무의미한 패턴**이다 — 그래서 이걸
명시적 복구 신호로 삼아도 정상 사용과 충돌하지 않는다. 감지하면 클라가 전 피어에 `force` 를
쏘고, 받은 기기는 IME 정렬에 더해 **최전면 앱을 비활성→재활성**해 꼬인 입력 세션을 끊는다
(`NSRunningApplication.activate` — 권한 불필요).

⚠ 왕복 도중의 중간 전환(`ko→en`)도 정상 동기화라 실제로 호스트에 전파된다. 그래서 복구
시점에 **IME 표시가 잠깐 깜빡이고 화면이 살짝 버벅인다** — 정상이다(IME 2회 + force 1회 + 바운스).

### 자동복구 (자동정정 + 포커스 바운스)

피어가 state 로 "나는 X다"라고 보고했는데 뷰어 최전면 기기(권한자)와 다르면 **자동으로
`recover` 를 보낸다** — 받은 기기는 IME 를 맞추고 **포커스 바운스까지** 한다. 어긋난 지
보통 1~5초 안에 **아무 키도 안 눌러도** 정상으로 돌아온다.

안전장치:
①상대의 **자기보고 이벤트**에만 반응(맹목적 주기 재적용 아님 — 하트비트 사고의 재발 방지)
②`recover` 는 **실제로 다를 때만** 적용한다. 이미 같으면 완전 무음 — **같은 값 재적용이
없으므로** 조합이 깨질 경로가 구조적으로 없다 ③적용했을 때만 바운스 ④2초 레이트리밋
⑤불일치를 보고한 **그 피어에게만** 전송 ⑥정정이 3회 연속 무효인 피어(유휴 세션)는 5분 백오프.

바운스가 거슬리면 `ime_sync.auto_recover: false` — IME 정렬만 하고 세션 복구는
캡스락 더블탭(수동)에 맡긴다.

수동 테스트 (수신측이 떠 있을 때):

```bash
python3 - <<'PY'
import json, os, socket, time
tok = json.load(open(os.path.expanduser("~/.config/macbridge/config.json")))["token"]
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.sendto(f"{tok} ko {int(time.time()*1000)}".encode(), ("<상대IP>", 8765))
PY
```

## 설계 메모

- **앱 한정 가드** — `ime_sync.only_app`. 로컬 작업 중 언어를 바꿨다고 상대 맥까지 따라 바뀌면 성가시기 때문. 부수 효과로 **양방향 설치에서 송신 주체가 자동으로 정해진다.**
- **하트비트는 기본 꺼져 있다**(`heartbeat_sec: 0`). "변화가 없어도 되풀이해 알려 어긋남을 자동 정정"하려던 기능인데,
  수신측이 **같은 값을 재적용**하는 경우가 생기고 **`TISSelectInputSource` 재호출이 조합 중인 한글을 리셋**해
  오히려 주기마다 자소분리를 만들었다(2026-08-06 실사용). 켜지 않기를 권한다.
- **에코 루프 방지** — 수신해서 입력 소스를 바꾸면 변경 알림이 또 발생한다. 그대로 두면 되쏘아 무한 왕복이 되므로 수신 직후 1초간 송신을 억제한다(`Suppressor`). 양방향에서는 이게 유일한 방어선이다.
- **"이미 그 언어인가" 는 캐시가 아니라 실제 상태로 판정한다** — 사용자·앱이 입력 소스를 독립적으로 바꾸기 때문. 캐시로 판정하면 드리프트가 생겼을 때 정정 요청이 조용히 무시돼 **자소분리가 고착된다**(2026-08-06 실사용에서 발생, 수정됨). TIS 조회가 0~3ms 라 매번 읽어도 공짜다.
- **접근 제한** — `allow_from` 대역 + 공유 토큰의 두 겹. 포트는 열려 있지만 둘 다 통과해야 처리한다.
- **UDP를 쓰는 이유** — TCP는 한 줄 보내려고 3-way 핸드셰이크를 먼저 하는데, 그 왕복이 곧 "Caps Lock 누르자마자 친 키가 깨지는" 경합 창이 된다. 유실 대비는 **같은 값 3회 중복 전송**으로 한다(수신측이 중복을 무시).
- **감지 방식** — `kTISNotifySelectedKeyboardInputSourceChanged` 분산 알림 + 50ms TIS 폴링 병행. **Caps Lock이든 메뉴바 클릭이든 방법을 가리지 않고**, 입력 모니터링·손쉬운 사용 권한이 필요 없다(Karabiner와의 결정적 차이).
- **로그의 "편도 Nms" 는 시계차가 지배한다.** 두 기기 NTP 오차가 그대로 실린다 — 부호가 뒤집히거나 값이 일정하면 오프셋, 흔들리면 네트워크.

## 한계

- 한글 **조합 중**에 전환하면 마지막 글자가 소실될 수 있다(간헐적). 지연이 0이어도 동일한 macOS IME 동작이라 구조적으로 못 없앤다.
- **`Ctrl`/`Shift`/`Cmd` 가 원격에 물리는 건 이 도구와 무관하다.** macbridge 는 키 이벤트를 **하나도** 만들지 않는다(`TISSelectInputSource` 만 호출). 원격 도구에서 modifier 를 누른 채 포커스가 바뀌면 keyup 이 호스트에 도달하지 못해 눌린 채로 남는 것으로, 원격 도구 공통의 문제다. **각 modifier 를 한 번씩 톡 눌렀다 떼거나** 뷰어 창 포커스를 뺐다 넣으면 풀린다.
  ⚠ 증상이 엉뚱하게 나타난다 — 실제 사례: `Cmd` 가 물린 채 한글을 치자 `d` 가 전부 `Cmd+D`(메모 복제)로 먹혀 Notes 에 메모가 9개 복제됐다.
- **클라 쪽에서 `Caps Lock` 이 로컬 입력 소스를 바꾸도록 켜 두어야 한다** (시스템 설정 → 키보드 → 입력 소스 → 편집). "로컬 전환을 감지"하는 구조이기 때문.
- `peers` 는 IP 만 받는다(이름 해석을 전송 경로에 얹지 않으려고).
